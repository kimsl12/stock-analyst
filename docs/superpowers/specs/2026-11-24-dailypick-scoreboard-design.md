# 데일리픽 사후 평가 시스템 (성적표) — 설계

작성 2026-11-24 · 상태: 승인 (2026-11-24 대화에서 항목별 확정)

## 1. 의도

대시보드 최상단 "오늘의 추천 종목"(DailyPick)은 매일 매수 추천 1건을 낸다. 지금은 그 픽이 맞았는지 볼 곳이 없다.
목적은 **데일리픽의 신뢰도와 수익률**을 숫자로 보여 주는 것 — "데일리픽을 따라 사도 되는가"에 답하는 페이지.

- 데일리픽은 **항상 매수 추천만** 낸다(매도 픽 없음). 평가는 전부 "샀다면" 기준.
- 픽 자체는 매일 바뀌어 단기 성격이 강하지만, 근거가 되는 종목분석의 목표가는 12개월 시야다 → **단기·장기 두 층**으로 평가한다.
- 사용자 판단: **6개월(약 120거래일) 표본이면 신뢰할 만한 지표**로 본다.

## 2. 목표 / 비목표 / 안티목표

목표

- 단기 리뷰(픽 1건 = 1평가): 5·20 거래일 수익률, 시장 대비 초과수익, 적중 여부. 메인 = 20일.
- 장기 리뷰(추천 1건 = 1평가, 중복 픽 묶음): 60·120·250 거래일 수익률·초과수익, 250일 내 목표가 도달 여부. 메인 = 120일.
- 점수대별(75–77 / 78–80 / 81+) 성적 — 점수가 높을수록 더 맞는지.
- 장세별 성적 — 픽 당일 레짐(리스크온/오프·가중치 세트)별.
- 종목 쏠림 지표 — 종목 균등가중 적중률 + 상위 종목 비중.
- 5/14 이후 전 기간 소급 채점.
- 완전 자동: 매일 가격 채점 + 매주 논지 판정, 사람 개입 불필요.

비목표

- "매수했어요"(Supabase `trade_log`) 실매수 성과 합산 — 별도 요청 시.
- 매도 신호 평가, 실시간(장중) 갱신, 일일 경로에 LLM 투입.

안티목표 (기술적으로 돌아가도 실패)

- 실행할 때마다 숫자가 흔들림 (논지 판정 재실행으로 묶음이 바뀌는 것 포함).
- 한 종목(NVDA 23회)이 전체 성적을 좌우하는데 화면에서 안 보임.
- 평가 기간이 덜 찬 픽을 실패로 집계.

## 3. 현황 (조사 결과)

- 픽 생성: `web/scripts/build_daily_pick.mjs` → `web/src/data/daily_pick.json` (+ `daily_pick_history.json`: 최근 ~32건, `{date,ticker,score}` 만 — 로테이션용, 평가에 부족).
- 자동 실행: launchd `com.stockanalyst.daily-pick` (Mac mini, KST 00:05) → `scripts/daily_pick_update.sh` (pull → build → 변경 시 commit/push → Vercel + Cloudflare 배포).
  - **주의**: 스크립트는 `daily_pick.json` 무변경 + KB 무변경이면 step 4 에서 조기 종료한다.
- git 이력: `daily_pick.json` 커밋 271회 → **161 픽-일 (2026-05-14 ~ 11-24), 고유 종목 42개, 2회 이상 픽된 종목 25개(픽 144건)**. NVDA 23·TSM 15·MSFT 12회.
- 과거 픽 데이터 결함: `tp_price` null 다수, `grade` 깨진 값(예: `강력매수 — TP $475,`), `buy_price` 가 픽일이 아닌 **분석일** 가격(11/19 LLY: 추천가 11/9 기준 $1,354 vs 당일 $1,382).
- 분석 원문: 최신 버전은 `analysis/{TICKER}_{Name}_v{N}/` (gitignore, 로컬 전용), 구버전은 `analysis/_archive/{TICKER}_{Name}_v{N}_{YYYYMMDD}.tar.gz` 에 **전 버전 보존**(scorecard.md·business.md·financial.md·risk.md·data.json 등). 신형 버전에는 `_report_data.json`(`thesis.claim/variant`, `executive_summary`)도 있음.
- 종목별 버전 이력: `analysis/_history/{TICKER}_*_timeline.json` (`history[].v/date/score/grade/target_price/folder`).
- 장세: `knowledge-base/market/regime.json` (risk_regime·trend·vol_regime·weight_set·fear_greed…) — git 이력 2026-06-11부터 120일치.
- 기존 유사 도구: `scripts/score_recommendations.py` (yfinance 채점, 브리핑 추천용), 애널리스트 성적 페이지 `web/src/pages/analyst/scoreboard.astro` (+ `web/scripts/lib/analyst_identity.mjs`).
- 주간 예약: Claude 앱 예약 작업 `outcome` = **매주 토요일 19:00 `/성과리뷰`** 실행 후 main 직접 커밋·푸시. 명령 정의 `.claude/commands/성과리뷰.md` (애널리스트 outcome_eval 후속 단계도 여기 있음).
- 감시: `scripts/automation_watchdog.sh` (KST 06:40/10:30, `scripts/notify.sh` 알림).

## 5. 데이터 설계

모든 파일은 git 추적(Vercel 빌드 컨테이너엔 analysis/ 가 없으므로 페이지는 커밋된 JSON 만 읽는다).

### 5.1 픽 원장 `web/src/data/daily_pick_ledger.json`

픽 1건 = 1행, append-only. 필드:
`date, ticker, name, market(US|KRX), score, grade(정규화), version, analysis_dir, analysis_date, tp_price, reasons[], regime{risk_regime, weight_set, trend, vol_regime, fear_greed} | null`

- **소급**: 1회성 스크립트가 `git log -- web/src/data/daily_pick.json` 의 각 커밋을 읽어 재구성. 같은 날 여러 커밋이면 **그날 마지막 커밋**(그날 사이트에 가장 오래 노출된 값)을 채택 — _내 판단_.
- **정규화**: grade 는 enum(강력매수/매수)로 정리, 깨진 값은 선두 등급어만 추출. `tp_price` null 은 해당 버전 scorecard(최신 폴더 또는 `_archive` tar.gz)에서 `web/scripts/lib/scorecard_parser.mjs` 의 `parseTargetPrice` 로 재추출, 실패 시 timeline.json 의 `target_price` (문자열 `$755` 형식 → 숫자), 그래도 없으면 null 유지.
- **regime 소급**: `git log -- knowledge-base/market/regime.json` 에서 픽일(KST) 당일 또는 직전 최신 스냅샷. 2026-06-11 이전 픽은 `null` ("기록 없음").
- **이후**: `build_daily_pick.mjs` 가 픽 생성 시 원장에 1행 append (같은 date 행이 있으면 교체 — 당일 재생성 대응). regime 은 그 시점 `regime.json` 에서.
  - 주의: `daily_pick_update.sh` 는 pull 전에 `git checkout -- web/src/data/` 로 작업트리를 리셋한다 → 원장 행은 같은 회차 안에서 반드시 커밋되어야 하며(커밋 실패 시 다음 회차 build 가 재생성), 리셋 대상에서 원장을 잃지 않도록 커밋 경로를 설계.
- grade 정규화 보강 — _내 판단_: 등급어 자체가 없는 과거 값(예: `— TP $295`)은 해당 버전 scorecard 에서 `parseGrade` 로 재추출.
- `daily_pick_history.json` 은 로테이션 용도로 그대로 둔다(건드리지 않음).

### 5.2 논지 판정 `web/src/data/daily_pick_thesis.json`

중복 픽(같은 ticker 의 2번째 이후 픽) 1건 = 1행:
`date, ticker, anchor_date, anchor_version, version, verdict(동일|보강|전환), rationale(한 줄), judged_at, judged_by("auto-same-version"|"agent")`

- **override** `web/src/data/daily_pick_thesis_overrides.json`: `{ "<ticker>@<date>": "전환" }` 형식. 판정 파일보다 우선.
- 동결: 한 번 기록된 행은 재판정하지 않는다(override 만 결과를 바꿈).
- override 연쇄 — _내 판단_: override 가 어떤 픽의 묶음 경계(전환 여부)를 바꾸면, 같은 ticker 의 그 이후 판정 행은 옛 anchor 기준이라 무효 → 해당 행들을 삭제하고 다음 토요일 회차가 새 anchor 기준으로 재판정한다(미판정 목록 스크립트가 "저장된 anchor ≠ 재계산 anchor" 행을 무효로 검출). override 는 드문 수동 조치라 재판정 비용은 무시 가능.
- 버전 식별 — _내 판단_: 과거 커밋 일부(약 8 픽-일)에서 `version` 과 `analysis_dir` 이 불일치(예: AMZN `v2` vs `AMZN_Amazon_v3`) → **`analysis_dir` 을 버전의 진실**로 쓴다(자동 동일 판정·아카이브 조회 모두).

### 5.3 채점 결과 `web/src/data/daily_pick_eval.json`

스크립트 산출물(매일 전체 재계산). 페이지가 그대로 렌더할 수 있도록 집계까지 포함:
`generated_at, picks[](단기 행), recommendations[](장기 행), summary{short, long}, by_score_band, by_regime, concentration, pending{unjudged_count, oldest_unjudged_date}`

## 6. 평가 규칙

### 6.1 공통

- **진입가**: 픽일(date) 이후 해당 종목 거래소의 **첫 거래일 종가**. 픽은 KST 00:05 생성 → KR 은 같은 날 장, US 는 같은 날짜(ET) 세션이 첫 바. 즉 "바 날짜 ≥ 픽일"인 첫 바의 종가.
- **N거래일 수익률**: 진입 바로부터 N번째 바의 종가 / 진입가 − 1. 휴장일은 바가 없으므로 자연히 건너뜀.
- **벤치마크**: US 종목·ETF = S&P500(`^GSPC`), KR = KOSPI(`^KS11`, KOSDAQ 종목도 KOSPI 로 통일 — _내 판단_). 원장 `market` 은 KRX 만 구분하므로 종목 가격 조회용 `.KS`/`.KQ` 접미사는 별도 맵으로 관리. 같은 진입·평가 날짜로 계산. 초과수익 = 종목 수익률 − 벤치마크 수익률 (%p).
- **적중**: 해당 기간 초과수익 > 0. 절대수익률은 별도 표시.
- **평가 대기**: 기간이 아직 안 찬 행은 해당 기간 칸 `대기`, 집계에서 제외.
- **표본 표시**: 모든 집계 칸에 n 표시. n < 10 이면 "표본 적음" 표식(숫자는 보여 줌) — _내 판단_.

### 6.2 단기 리뷰 (픽 단위)

- 모든 픽을 개별 평가(같은 종목 재픽도 각각) — "그날 사도 됐나 / 매수 시점" 검증.
- 기간: 5·20 거래일. 메인 적중 = 20일.

### 6.3 장기 리뷰 (추천 단위)

추천 1건을 "샀다가 파는 포지션"처럼 다룬다 (사용자 확정: 다안 + 전환 시점 마감).

- **시작**: 같은 ticker 의 첫 픽, 또는 직전 추천이 마감된 뒤의 첫 픽이 새 추천의 anchor. 진입가 = anchor 픽의 진입가(§6.1).
- **진행 중 재픽**: 추천이 열려 있는 동안 같은 ticker 가 다시 뽑히면 논지 판정(§7):
  - `동일`·`보강` → 같은 추천에 "재추천"으로 편입 (횟수·날짜·판정 근거 기록).
  - `전환` → 기존 추천을 마감하고 그 픽이 새 추천의 anchor.
  - 미판정 → 그 픽은 "판정 대기". 해당 ticker 의 그 픽 이후 구간은 묶음이 확정될 때까지 장기 집계에서 제외(기존 추천은 잠정적으로 계속 진행 표시).
- **마감**: 아래 중 **시간상 먼저** 오는 것.
  | 마감 사유 | 시점 | 청산가 |
  |---|---|---|
  | 달성 | 진입 후 첫 **일중 고가 ≥ 목표가** 바 | 목표가 (그 바 시가가 이미 목표가 위면 시가) — _내 판단_ |
  | 논지 교체 | `전환` 판정 픽의 진입 바 | 그 바 종가 (= 새 추천 진입가) |
  | 만기 | 진입 후 250번째 바 | 그 바 종가 |
  - 벤치마크 청산 = 같은 날짜 바의 종가.
  - 목표가는 **각 추천 anchor 분석의 목표가**(옛 논리=옛 목표가, 새 논리=새 목표가). tp 없으면 "달성" 마감은 발생하지 않고 "목표가 없음"으로 분리 표시.
  - 달성·만기로 마감된 뒤 같은 ticker 가 다시 뽑히면 판정 없이 바로 새 추천 (판정 대상은 "열린 추천 중의 재픽"만 → 실제 판정 건수는 119 이하).
- **기간 값**: 60·120·250 거래일 수익률·초과수익. **마감 이후 칸은 마감 값으로 고정**("시스템을 따라 사고, 시스템이 끝냈을 때 팔았다면"). 마감된 추천은 경과일과 무관하게 모든 칸이 확정값 → 평가 완료로 집계. 열린 추천은 기간 미도달 칸만 `대기`.
- **메인 적중** = 120일 칸 초과수익 > 0 (마감 고정값 포함).
- **표시**: 마감 사유 분포(달성 / 논지 교체 / 만기 / 진행 중), 목표가 도달률 = 달성 마감 수 ÷ (tp 있는 마감 추천 수), 달성까지 평균 거래일.
- 예: NVDA 추천① 진입 $180 → 50일째 `전환` 픽, $182 → ① "논지 교체" 마감 +1.1%(시장 대비 −0.8%p, 미적중) / 추천② $182 에서 새 목표가로 시작.

### 6.4 분해 집계

- 점수대: <78 / 78 이상 <81 / 81 이상 (소수점 점수 대응, 화면 표기는 75–77 / 78–80 / 81+). 단기는 픽, 장기는 anchor score 기준.
- 장세: 픽(또는 anchor)의 `regime.weight_set` 별, null 은 "기록 없음".
- 쏠림: (a) 종목 균등가중 적중률 = 종목별 적중률의 평균, (b) 픽 수 상위 5종목 비중 %, (c) 종목별 픽 수·적중률 표.

## 7. 논지 판정 (에이전트)

- **대상**: 열린 추천 중의 재픽 가운데 판정 파일·override 에 없는 것 **전부** (기간 제한 없음 → 한 주 실패해도 다음 주에 회수). 추천의 열림/마감 상태는 가격(목표가 도달·만기)에 의존하므로, 미판정 목록 스크립트는 채점 결과(`daily_pick_eval.json`)의 추천 상태를 읽어 대상을 정한다. 시간순으로 앞선 픽이 미판정이면 그 뒤 픽은 대상에서 보류(anchor 미확정).
- **자동 동일**: 픽 버전 == anchor 버전이면 에이전트 없이 `동일`, `judged_by="auto-same-version"`.
- **비교 대상 고정**: 직전 픽이 아니라 **현재 추천의 anchor** 논지와 비교 (점진적 표류 누적 방지).
- **원문**: anchor·대상 버전 각각의 scorecard.md (+ 있으면 `_report_data.json` thesis/executive_summary, business.md 핵심부). 최신 폴더 없으면 `_archive` tar.gz 를 임시 디렉토리에 풀어 읽는다.
- **기준표 3항목**: ① 핵심 성장 동력 ② 밸류에이션 근거(왜 지금 사도 되는가) ③ 핵심 촉매·리스크.
  - 셋 다 같음 → `동일` / ①이 같고 ②③에 근거 추가·갱신 → `보강` / ①이 바뀜(다른 사업·다른 수요 동인이 주 논거) → `전환`.
  - rationale 예: `v6 근거=데이터센터 GPU 수요 / v14=동일 + Blackwell 램프 → 보강`.
- **실행 주체**:
  - 소급 1회: 이번 구현 중 메인 세션이 종목별 general-purpose 에이전트를 병렬로 돌려 144건 처리. 에이전트는 판정 행만 반환, 파일 기록·커밋은 메인.
  - 이후: `/성과리뷰`(토 19:00 예약) 에 후속 단계 추가 — 미판정 목록 산출 스크립트 실행 → 판정 → `daily_pick_thesis.json` 기록 → 채점 스크립트 재실행 → 명시 경로 커밋.
  - 목록 산출은 결정적 스크립트(anchor·버전·아카이브 경로까지 출력)로 만들어 에이전트가 고를 일이 없게 한다.

## 8. 자동화

- **매일 (launchd daily-pick)** `scripts/daily_pick_update.sh`:
  1. `build_daily_pick.mjs` (원장 append 포함)
  2. **새 단계**: 채점 스크립트 → `daily_pick_eval.json`
  3. 변경 감지(step 4)와 `git add`(step 6) 대상에 원장·eval 포함. eval 은 가격 변동으로 매일 바뀌므로 사실상 매일 커밋·배포(이미 픽이 거의 매일 바뀌므로 부담 증가 미미).
  - 채점 실패 시: notify + 기존 eval 유지, 픽 발행은 계속.
- **매주 (토 19:00 `/성과리뷰`)**: §7 판정 단계.
- **감시 (`automation_watchdog.sh`)** 추가 점검 2개: eval `generated_at` 이 2일 초과 경과 → 경고 / `pending.oldest_unjudged_date` 가 14일 초과 → 경고.
- **Vercel prebuild**: 채점 스크립트는 prebuild 에 넣지 않는다(커밋된 eval 사용, 빌드 시 네트워크·python 의존 회피).
