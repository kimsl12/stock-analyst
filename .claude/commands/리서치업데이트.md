$ARGUMENTS 를 대상으로 **research-curator** 를 수동 호출해줘.

## 명령 정보

- **에이전트:** research-curator (Opus)
- **데이터 흐름:** 웹검색 + WebFetch → `knowledge-base/research/` 3-레이어 (L1/L2/L3)
- **독립성:** briefing-lead Phase 0-A 자동 호출과는 별개. 본 명령은 즉시 수동 트리거 전용.

## 인자 형식

```
/리서치업데이트 <주기> [섹터?]
```

**주기 (필수):**
- `주간` — L1 헤드라인 인덱스 갱신 (5섹터 × 4유형, 5~10분)
- `월간` — L2 요약본 작성 (섹터별 3~5건, 30~60분)
- `분기` — L3 분기 Deep Dive HTML (반도체·에너지 우선, 60~120분)
- `검증` — 기존 인용 검증 (URL 살아있는지, 페이지·날짜 정확한지)

**섹터 (선택):**
- `반도체`, `에너지`, `매크로`, `바이오`, `핀테크`
- 미지정 시 5섹터 전체

**예시:**
```
/리서치업데이트 주간                  # 5섹터 헤드라인 일괄
/리서치업데이트 월간 반도체           # 반도체만 L2 요약
/리서치업데이트 분기 에너지           # 에너지 L3 Deep Dive HTML 발행
/리서치업데이트 검증                  # 전체 인용 검증
```


실행 후 위 프롬프트의 `today`, `today_dow` 에 실제 값 주입.

## 분기 발행 조건 (project_research_kb_phase5 메모리)

`/리서치업데이트 분기 {섹터}` 호출 시 다음 조건 사전 확인:
- Phase 1~4 완료 (인프라 + 4개 분석 에이전트 통합)
- 해당 섹터 L2 요약본 ≥ 5건 누적
- 우선순위: 반도체 → 에너지 → 매크로 → 바이오 → 핀테크

조건 미충족 시 research-curator 가 그 상태 보고 후 quarterly 호출 거부 (사용자 강제 옵션 제공).

## 워크플로 (research-curator)

`.claude/agents/research-curator.md` 의 Mode A~E 워크플로 참조.

## 실패 처리

- 학술 사이트 403/paywall → preprint (arXiv/bioRxiv/medRxiv/SSRN) 대체 검색
- 모두 실패 → abstract 만 수집 + `[paywalled: abstract only]` 마커
- WebFetch 1회 실패 → 1회 재시도 → 실패 시 해당 항목 미수집 + 다음 진행
- 시간 cap 초과 → 현재까지 산출물 저장 + 미완료 항목 보고
