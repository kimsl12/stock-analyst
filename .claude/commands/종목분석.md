# 종목분석 오케스트레이션 [v3.7 — main-loop orchestrator 방식]

사용자가 `/종목분석 $ARGUMENTS` 를 실행했습니다. **메인 루프가 직접 오케스트레이터 역할**을 수행하여 서브에이전트를 순차·병렬 호출합니다.

> ⚠️ v3.6 이전의 `agent: stock-analyst-lead` 자동 위임 방식은 폐기됨.
> 이유: 서브에이전트 런타임에서 nested Agent tool 이 박탈되어 `stock-analyst-lead` 가 다른 서브에이전트를 호출하지 못하는 구조적 한계 존재. 메인 루프가 직접 호출하면 모든 서브에이전트에 Agent tool 정상 접근 가능.

---

## 실행 절차

### Step 0: 스펙 Read
메인 루프는 먼저 `.claude/agents/stock-analyst-lead.md` 를 Read 하여 **전체 파이프라인 스펙**을 습득한다.
이 문서에는 Step -2 ~ Phase 4 까지의 상세 절차, ETF 판별 기준, 각 서브에이전트 호출 프롬프트 템플릿, 검증 체크리스트가 포함되어 있다.

### Step -2: 세션 부트스트랩
`session-bootstrap.md` Read → 마지막 작업·유효 analysis·KB 상태 파악.

### Step -2.5: Bootstrap Stale 검증
"진행 중 작업" 필드에 Git 오류·push 보류 언급이 있으면 `git status && git log -1 --oneline` 로 실제 상태 직접 확인. Clean 이면 bootstrap 즉시 갱신 후 진행.

### Step -2.6: TodoWrite 등록
아래 6개 Phase 를 todo 로 등록:
1. Phase 0-A: KB 갱신 판정 + kb-updater 호출
2. Phase 0-B: fetch_price.py 실시간 주가 + ATR 수집
3. Phase 0-D: 파일 스캐폴딩
4. Phase 1: 병렬 분석 (5~6 에이전트)
5. Phase 2: scorecard-strategist 종합
6. Phase 3: report-generator HTML + git commit/push + bootstrap 갱신

### Step 0: 분석 유형 판별 (리드 스펙 따름)
ETF 판별 기준 적용 → 개별 종목 또는 ETF 분기.
- 개별 종목: 본 스킬 워크플로우 A 진행
- ETF: **etf-lead 서브에이전트 단독 호출** (etf-lead 내부도 data-collector → etf-analyst → report-generator 순차 호출)

### Phase 0-A: KB 갱신
```
Agent(kb-updater) 호출 with {
  prompt: "섹터: {주력섹터}, sub_sectors: [...], macro_tags: [...]. 
           valid_until > 오늘 이면 생략 응답. 아니면 웹검색으로 KB 갱신."
}
```

### Phase 0-B: 실시간 주가
메인 루프가 직접 Bash 실행:
```bash
python scripts/fetch_price.py {종목코드|TICKER}
```
→ 출력 JSON 에서 current_price, atr_14, stop_loss_2atr, target_3atr 추출.

### Phase 0-D: 파일 스캐폴딩
`analysis/{종목코드}_{종목명}/` 디렉토리 생성 + 빈 템플릿 7종(data/company/financial/business/momentum/risk/scorecard) Write.

### Phase 1: 병렬 분석 (한 메시지에 5개 Agent 호출 동시)
```
Agent(company-overview)  → analysis/{}/company.md
Agent(financial-analyst) → analysis/{}/financial.md
Agent(business-analyst)  → analysis/{}/business.md
Agent(momentum-analyst)  → analysis/{}/momentum.md
Agent(risk-analyst)      → analysis/{}/risk.md
```
각 프롬프트는 `stock-analyst-lead.md` 의 "Phase 1 호출 템플릿" 섹션 그대로 사용.

### Phase 2: 스코어카드
```
Agent(scorecard-strategist) with {
  prompt: "analysis/{}/{company,financial,business,momentum,risk}.md 5개 파일을 읽어 
           10항목 가중 스코어카드 + ATR 기반 손절/목표가 + 투자 전략 작성. 
           가격 데이터: current_price={}, atr_14={}, stop_loss_2atr={}, target_3atr={}."
}
```
→ analysis/{}/scorecard.md

### Phase 2.5: 리드 통합 검증 (메인 루프 직접 수행)
`stock-analyst-lead.md` 의 "리드 통합 검증" 섹션 체크리스트 적용:
- 시총 = 현재가 × 발행주식수 일치
- 52주 범위 내 현재가
- PER = 시총 / 순이익 역산
- 손절가 < 현재가 < 목표가

### Phase 3: HTML 리포트
```
Agent(report-generator) with {
  prompt: "analysis/{}/*.md 7종을 읽어 reports/{종목코드}_{종목명}_{YYYYMMDD}.html 생성. 
           report_template.py 호출."
}
```

### Phase 3.5: Git + 일회성 산출물 정리
```bash
git add analysis/ reports/{}/ session-bootstrap.md
git commit -m "feat(analysis): {종목} ..."
git push origin main

# 일회성 산출물 삭제 (커밋되지 않은 temp 파일만)
rm -f generate_{종목코드}.py {종목코드}_report_data.json scripts/_tmp_*.txt
```

### Step 최종: session-bootstrap.md 갱신
"마지막 작업", "analysis/ 유효 파일" 목록 최신화 + Edit 후 별도 커밋(optional).

## 서브에이전트 호출 실패 시 (Fallback)

특정 서브에이전트 호출이 토큰 한도·런타임 오류로 실패하면:
1. TodoWrite 에 해당 Phase 를 blocked 상태로 유지
2. 사용자에게 현재 상태 보고 (완료/실패/미시작 Phase)
3. 선택지 A/B/C 제시 (축소 리포트 / 새 세션 이어쓰기 / 중단)

## 최종 산출물
1. 텍스트 Executive Summary (투자 의견, 목표가, 손절가, 핵심 논쟁 포인트)
2. HTML 리포트 (`reports/{종목코드}_{종목명}_{YYYYMMDD}.html`)
3. GitHub push 완료 (Actions 복구 시 gh-pages 자동 배포)
4. session-bootstrap.md 갱신
