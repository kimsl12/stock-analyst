agent: briefing-lead
---

$ARGUMENTS 인자로 **내 포트폴리오 v2** 를 실행해줘.

## 명령 정보

- **목적:** 사용자 1인의 개인 보유 자산 처방 (공개 콘텐츠가 아님 → **면책 완전 제거**)
- **산출물:** `reports/briefing/user_portfolio_{YYYYMMDD}.html`
- **격리:** 다른 모든 명령은 `knowledge-base/portfolio/user_portfolio.md` 를 읽지 않는다. 본 명령만 유일한 진입점.
- **실행 주기:** 주 1회 권장 (주간 리포트 직후, 클로드 데스크탑 루틴)

## 인자 해석

- 인자 없음 → **인터랙티브 모드** (미등록 항목 입력 요청)
- `--view` → 조회만 (입력 받지 않음)
- `--html` → HTML 생성 (기본)

## briefing-lead 에 전달할 컨텍스트

```
mode: user_portfolio_v2
interactive: true | false (--view 시 false)

phase_0_dependency_check:
  - analysis/briefing/lead_weekly_*.md 최근 7일 내 존재 여부 확인
  - 없으면 → ⚠️ 경고 표시 + fallback 모드 (자산군 비교만, 강력 권고 생략)
  - 있으면 → 정식 v2 모드 진행

phase_1_input_collection:  # read-only, 재분석 X
  - knowledge-base/portfolio/user_portfolio.md
  - knowledge-base/portfolio/model_portfolios.md
  - analysis/briefing/lead_morning_*.md (최근 7일치)
  - analysis/briefing/lead_evening_*.md (최근 7일치)
  - analysis/briefing/lead_weekly_*.md (최근 1건)
  - knowledge-base/market/* (지수·환율·원자재 스냅샷 — 개별 종목 가격 X)

phase_1_5_price_fetch:  # ★ 신규 (필수, hallucination 차단)
  - 트리거: Phase 2-1 후보 풀 추출 직후, Phase 2-4 강력 권고 작성 직전
  - 대상: 사용자 보유 종목 + 추천 후보 종목 (총 12~15개 예상)
  - 실행: Bash 단일 호출
      python scripts/fetch_price.py {ticker1} {ticker2} ... {tickerN}
    * 미국: 알파벳 티커 (GLD, SOXX, XLE, AMZN 등) → yfinance
    * 한국: 6자리 숫자 (012450, 000660 등) → pykrx
  - 산출: JSON (stdout) + analysis/{ticker}_price.md (개별 파일)
  - 결과 통합: analysis/briefing/user_portfolio_prices_{YYYYMMDD}.json
    각 티커별 {current_price, atr_14, high_52w, low_52w, name}

  ★ JSON_OUTPUT 블록 파싱 의무 [v3.13]
    - stdout 에서 `JSON_OUTPUT_START` ~ `JSON_OUTPUT_END` 사이 블록만 파싱
      예: python3 scripts/fetch_price.py {tickers...} \
            | awk '/JSON_OUTPUT_START/{flag=1;next}/JSON_OUTPUT_END/{flag=0}flag'
    - 블록 외 stdout 출력(경고·로그·진단 메시지)은 **전부 무시**
      특히 "KRX 로그인 실패: KRX_ID 또는 KRX_PW 환경 변수..." 메시지는 단순 경고로,
      pykrx 자체는 정상 작동하며 한국 종목 가격은 JSON 블록에 포함됨
    - 추천 풀 / 가격 인용 가능 범위 = **JSON 블록에 포함된 티커 한정**
    - JSON 블록에 없는 종목 → "fetch 실패" 로만 처리. 다음 거짓 사유 작성 절대 금지:
      ❌ "pykrx 미설치", "yfinance 환경 오류", "Python 환경 누락"
      ❌ stdout 경고 메시지를 미설치 사유로 오독한 사례 일체
    - 한국 종목 fetch 실패 의심 시 → 반드시 JSON 블록 출력 결과로만 판단
      (사전 추측·환경 메시지 해석 금지)

  fail_handling:
    - fetch_price.py 실행 실패 (return code ≠ 0 OR JSON 블록 자체가 빈 배열)
      → graceful fail: 강력 권고 섹션 SKIP + "가격 데이터 미수집" 사유 명시
      → 자산군 비교 + 매크로 요약만 진행
    - 일부 종목만 JSON 블록에서 누락 → 해당 종목만 추천 풀에서 제외
      + 사유 표기 (반드시 "JSON 블록 미포함" 으로만 표기, 거짓 사유 금지)
    - 보유 종목 가격 ≠ user_portfolio.md 입력값 차이 5% 초과 → 경고 박스

phase_2_processing:
  2-1_candidate_pool:
    - 최근 7일 lead_*.md 본문에서 *매수·관심·추천·비중확대* 언급 종목 추출
    - 종목별 등장 횟수·최근성·언급 맥락 기록
    - debate-card / contrarian-card 에서 언급된 종목도 포함

  2-2_gap_analysis:
    - 사용자 보유 vs 가장 가까운 모델 포트폴리오의 자산군·섹터·지역 갭
    - 부족 (under) / 과대편향 (over) 영역 식별
    - 정량화: 현재 비중%, 목표 비중%, 갭 (%p)

  2-3_score_and_match:
    적합도 = 절대 매력도(0.35) + 갭 매칭(0.30) + 등장 빈도(0.20) + 최근성(0.15)
    각 후보 종목 0~100점 산출
    Top N (5~8개) 추출

  2-4_strong_buy:
    - 추천 종목별 4요소 의무 명시:
      ① 무엇 (티커·종목명)
      ② 왜 (이번주 어느 lead_*.md 어느 섹션에서 언급, 핵심 논리 1~2줄)
      ③ 어떻게 (절대 수량 N주 + 비중 %p + 진입가 구간 + 손절가 + 12M 목표가)
      ④ 적합도 (갭 매칭 / 절대 매력도 둘 중 하나 명시 + 점수)
    - "검토", "고려" 같은 약한 표현 금지 → "X주 매수" 단정 톤

  2-5_strong_sell:
    - 사용자 보유 중 과대편향·약화된 종목 대상
    - 동일 4요소 명시 (수량 + %p + 진입가 → 매도가)
    - 부분 매도 시 "Y주 매도, 잔여 Z주 보유" 명시

phase_3_html_delegation:  # ★ 신규 [v3.12] — 양식 강제
  - briefing-lead 가 HTML 직접 작성 **절대 금지**
  - 반드시 Agent(briefing-report-generator) 위임 (template=user_portfolio_v2)
  - 표준 양식: 2026-04-14 user_portfolio.html 채택
  - briefing-report-generator.md "★ user_portfolio_v2 전용 표준 양식" 섹션 참조
  - 자가 검증: footer 시그니처가 "briefing-report-generator" 인지 grep 확인
    "Generated by briefing-lead" 발견 시 즉시 폐기·재생성

phase_3_report_sections:
  1. 투자자 프로파일 (기존 유지)
  2. 보유 종목 + 자산군 현황 (기존 유지)
  3. [신규] 이번주 매크로 요약 (주간 리포트에서 3줄)
  4. [신규] 이번주 등장 종목 풀 (적합도 점수 표)
  5. [신규] 포트 갭 분석 (자산군·섹터·지역)
  6. [신규] 🔴 강력 매수 권고 (Top 매수 — 4요소 명시)
  7. [신규] 🔵 강력 매도/축소 권고 (4요소 명시)
  8. [신규] 다음 주 모니터링 포인트 (진입·손절 트리거)
  9. (기존) 4종 모델 포트폴리오 비교

required_actions:
  - knowledge-base/portfolio/user_portfolio.md 읽기
  - interactive=true 일 때 미등록 항목 input 요청
  - 사용자 입력 → user_portfolio.md 갱신 (briefing-lead 만 쓰기 가능)
  - 주간 lead_*.md 의존성 점검 → 없으면 fallback
  - 강력 권고 작성 시 추천 근거 4요소 누락 금지

forbidden:
  - HTML 출력 시 개인 데이터 평문 노출 (이름·계좌번호 등)
  - 다른 사용자에게 본 산출물 공유 가정
  - 면책 문구 삽입 (G-9, F-7, "투자 권유 아님" 등 일체 금지)
  - "검토 필요", "고려해볼 만함" 같은 약한 표현
  - debate-card / contrarian-card 생략 가능
  - 13F 시차 경고 불필요

  ## ★ 가격 인용 절대 금지 (hallucination 차단)
  - fetch_price.py 출력 외 가격 인용 금지
  - "daily_snapshot 기준", "KB market 기준" 등 거짓 출처 인용 금지
  - GLD/SLV 등 ETF 가격을 spot 가격에서 임의 환산 금지
    (예: "GLD ≈ Gold spot ÷ 17"  ← 절대 금지)
  - 사용자 보유 종목 평가금 ↔ 매수 권고 가격 불일치 시 → 분석 중단·재수집
  - 가격 미수집 종목으로 강력 권고 작성 금지 (추천 풀에서 자동 제외)

template: user_portfolio_v2

git_handling:
  - user_portfolio.md 는 git 추적 (현재 .gitignore 미설정)
  - 단, 향후 .gitignore 에 추가 검토 필요 (개인 데이터)
```
